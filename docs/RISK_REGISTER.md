# ZI-E Risk Register

This register tracks credible problems requiring prevention, detection, recovery, and
verification. It does not approve implementation or freeze unresolved hardware values.

| ID | Risk | Subsystem | Likelihood | Impact | Prevention | Detection | Recovery | Test strategy | Current status | Evidence/source |
|---|---|---|---|---|---|---|---|---|---|---|
| R-PROTO-001 | A stale or rebooted controller regains motion authority | ESP32–STM32 protocol | Medium | Critical | Hello creates a candidate only; require a fresh valid heartbeat; bind authority to configured controller and boot session; reject the immediately retired session; authenticated/persistent replay defense in later wire stage | Session mismatch/restart fault and audit log | Local safe stop, clear authority, renegotiate and recommission when required | Reboot/replay/fuzz/fault-injection tests | OPEN: Phase 2B1 blocks Hello-only authority and immediate retired-session replay; long-lived authenticated replay protection remains unimplemented for Phase 2B2 | OpenCyphal specification; micro-ROS reconnect issues #572, #912, #1809 |
| R-PROTO-002 | Duplicate/stale traffic masks a dead controller link | ESP32–STM32 protocol | Medium | Critical | Only newer valid heartbeat sequences refresh a verified monotonic deadline | Local link-expiry fault independent of command receipt | STM32 local safe stop; explicit reconnect | Duplicate, reorder, wraparound, delay, loss, and event-loop stall tests | MITIGATING: host contract scaffolded; hardware path unverified | PX4 issue #16944; OpenCyphal specification |
| R-PROTO-003 | Forged or corrupted frames trigger false restart/fault or unsafe authority | ESP32–STM32 protocol/security | Medium | Critical | Hello never grants authority; reject stray/incompatible Hellos without mutating a healthy session; select integrity/authentication after threat and bus analysis; never expose raw actuator frames | Rejection counters, unexpected-peer/session diagnostics, restart faults for configured-peer boot changes | Fail closed on established-session expiry/restart, rate-limit renegotiation, service diagnostics | Corruption, spoofing, stray-Hello, configured-peer spoof, bus-flood, and denial-of-service fault injection | OPEN: Phase 2B1 limits trivial Hello takeover/teardown; no wire authentication or integrity mechanism selected | Secure-boundary requirement; independent Phase 2B1 review |
| R-SAFE-001 | Healthy transport heartbeat masks a stalled safety task | STM32 safety supervision | Medium | Critical | Independent critical-task supervision plus hardware watchdog fallback | Per-task liveness channels and watchdog reset cause | Local safe state and controlled reboot | Stall each critical task while communications remain healthy | OPEN: Phase 2C design/bench work | Zephyr task watchdog documentation |
| R-PROTO-004 | CAN priority, bursts, or retries exceed a safety-message deadline | ESP32–STM32 protocol | Medium | Critical | Complete message inventory; conservative stuffing bounds; priority-aware response-time analysis; bounded diagnostics | Deadline misses, queue high-water marks, arbitration/error counters | Drop/defer noncritical traffic; STM32 local safe state | Simultaneous release, diagnostic burst, arbitration, ACK/bit-error injection | OPEN: rates, priorities, bitrate, and deadlines unverified | `PHASE2B2_BUS_TIMING_ANALYSIS.md`; Bosch CAN 2.0; Espressif TWAI docs |
| R-PROTO-005 | Multi-frame semantic message is partially executed, confused across sessions, or exhausts reassembly memory | ESP32–STM32 protocol | Medium | Critical | Bounded transaction identity/reassembly; complete-before-dispatch; session binding; strict size/time limits | Fragment gap/order/duplicate/timeout counters | Discard whole incomplete message; never partially command motion | Loss/reorder/duplicate/reboot/stale-session/memory-pressure corpus | OPEN: fragmentation design intentionally not frozen | 8-byte Classical CAN limit; current 12-byte semantic identities |
| R-EXT-001 | Extension self-asserts trust, uses malformed enum values to bypass class rules, or receives declared permissions as automatic grants | Plugins/security | Medium | Critical | External registry assignment binds package/trust/controller/profile; exhaustive enum checks; typed permission requests; deny-by-default enforcement before execution | Registration/context mismatch, validation issue, permission audit, runtime authorization denial | Reject/quarantine/disable extension; synchronously revoke capability exposure | Self-claimed built-in, package/profile impersonation, protected-controller claim, out-of-domain enum, permission escalation, and confused-deputy tests | MITIGATING: in-memory registry rejects identity/trust/ownership escalation and revokes capabilities; runtime enforcement still OPEN | Independent adversarial review; VS Code Workspace Trust/runtime security; Zi-E safety boundary |
| R-EXT-002 | Declared capability becomes commandable without validation, health checks, or commissioning | Hardware/plugins | Medium | Critical | Separate declared/validated/active sets; explicit lifecycle; only active/degraded records resolve; ambiguous providers rejected | Registry invariant checks and identity-bound capability resolution | Clear active capability synchronously; fail/degrade/quarantine/disable/remove extension | Activation-before-validation, unvalidated active set, ambiguity, lifecycle, and synchronous revocation tests | MITIGATING: in-memory activation/resolution contract implemented; loader, runtime authorization, and commissioning binding remain OPEN | ros2_control inactive hardware lessons; ROS 2 lifecycle failures; Zi-E commissioning rule |
| R-EXT-003 | Executable content is smuggled into a cosmetic asset pack | Assets/plugins/security | Medium | High | Data-only asset class; no entrypoint or permissions; later archive allowlist and parser limits | Package/schema scan and integrity validation | Reject/quarantine package; protected system fallback | Entrypoint/script/archive traversal/polyglot corpus | MITIGATING: manifest contract rejects entrypoint/permissions; file inspection still OPEN | VS Code distinction between code entrypoints and data contributions |
| R-EXT-004 | Failed, stale, or impersonated configuration partially replaces active settings or escalates extension authority | Plugins/configuration/security | Medium | Critical | Authoritative package/device/profile binding; staged validation; monotonic revision; atomic snapshot replacement; forbidden authority/raw-control namespaces; lifecycle commit gate | Configuration result, revision/generation audit, binding mismatch, lifecycle check | Preserve active snapshot and discard staged/validated candidate | Invalid rollback, stale revision, impersonation, disabled/quarantined/removed commit, authority escalation, unknown-domain tests | MITIGATING: in-memory transaction contract implemented; persistence crash recovery and real hardware application rollback remain OPEN | ROS 2 atomic parameters; Kubernetes resourceVersion conflict semantics; Home Assistant migration failure states |
